# Security engineering boundaries — G11

The threat model distinguishes random memory corruption, malformed program inputs, maliciously modified binaries, and hostile hosts. These are different problems and have different remedies.

**Native quantum guests:** the G11 quantum machine admits canonical 32-qubit stabilizer states and bounded instruction records, then checks program counters, remaining fuel, code-view attenuation, unique active owner IDs and return frames at every transition. Sixteen guest levels execute in the acceptance suite. A child receives exclusive ownership of the existing quantum bank while its parent is suspended. Guest instructions cannot express host pointers, arbitrary memory access or syscalls. This isolation applies to the quantum guest ISA; the self-hosted ANF64 native compiler can produce unrestricted native programs and is not a sandbox for untrusted native source. The G11 machine binaries use separate RX/RW ELF segments. They do not use KVM, OS guests or namespace virtualization.

**History admission:** the native reverse tool validates journal and seed lengths, checksums, canonical state fields, source instruction binding and inverse quantum transitions. Every canonical preimage, including overwritten entropy and guest control state, is retained. FNV checks are non-cryptographic; inverse checks are consistency checks, not remote attestation. Journals from untrusted origins require an independent authenticated digest. Native machine histories do not use the legacy triplicated-state ECC described below.

**Native memory and code:** the standalone seed and directly compiled Clifford images use RX opcode and RW state segments (ELF W^X). Each has triplicated ternary state and 64-row tableau. Bitwise majority corrects one disagreeing lane. The digest and its complement detect tested two-lane conflicting faults. Neither majority ECC nor FNV digest protects against a deliberate adversary who changes two replicas or recomputes the digest.

**Program packets:** the dense assembly translator emits a 48-byte QVU1 header and fixed-width canonical records. The assembly inspector independently checks format, bounds, semantics and FNV64. All 1,408 individual record payload-bit flips in the documented sample were rejected; 176 also executed through the refusal path. FNV64 is non-cryptographic; valid modified packets with a recomputed digest may pass unless checked against a trusted signed release manifest.

**Runtime isolation:** the standalone seed uses `PR_SET_NO_NEW_PRIVS` and Linux BPF seccomp (only its permitted minimal syscalls). The dense runtime validates and loads program data then installs a Linux seccomp BPF policy before quantum-state operations. The policy filters syscall architecture and blocks x32 entry, but allows a bounded set of memory, I/O and runtime-related syscalls needed by libc. A probe build executes a forbidden `getpid` after BPF activation and reaches the success path only after the kernel rejects it with `-EPERM`. This is kernel-enforced process isolation, not an escape-proof VM.

**Supply-chain authenticity:** `MANIFEST_SHA256.txt` lists all release files except its own detached signature and checksum metadata. `release_manifest.ed25519.sig` signs the raw manifest with Ed25519; `release_public_ed25519.pem` supplies the verification key. `VERIFY_RELEASE.sh` checks the signature and each file hash. Because the public key accompanies the archive, independently pin its SHA-256 fingerprint before trusting the publisher identity. The signing private key is not in the release. The signature does not create on-CPU runtime attestation and does not prevent malicious hypervisors or kernels from altering a running process.

**Outside verified scope:** firmware trust, silicon attestation, fault-tolerant quantum hardware, adversarial physical side channels, malicious-kernel isolation, Windows/ARM64 execution and OS/hypervisor nested virtualization. Machine-defined quantum guest nesting is tested as described above. The dense executor does not triplicate its exponentially sized amplitude buffer; tested one-lane memory correction applies to the separate legacy seed/Clifford state.
